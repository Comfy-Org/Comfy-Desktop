# ComfyBuilder Artifact Compatibility Gaps

## Executive Summary

ComfyBuilder's Kubernetes builder produces a directory layout that is compatible with the ComfyUI Desktop installer. This layout contains the `standalone-env` directory, the `ComfyUI` source tree, and a `manifest.json` metadata file. This output is packaged as a `.tar.gz` archive. Desktop's extraction system supports `.tar.gz` files on all platforms using a bundled copy of 7za, which means the archive format requires no modifications.

The current implementation has two major limitations. First, the actual build matrix only supports the `linux-nvidia` target. Second, the fake builder used in the single-binary demo does not compile a real distribution. It writes a stub JSON file instead of a compressed environment. Only the `linux-nvidia` platform target is end-to-end installable today when running the real Kubernetes builder.

### Desktop Platform Variants

Desktop supports the following 11 platform variants:
1. `win-nvidia` (Supported by ComfyBuilder: No)
2. `win-nvidia-cu128` (Supported by ComfyBuilder: No)
3. `win-nvidia-cu126` (Supported by ComfyBuilder: No)
4. `win-intel-xpu` (Supported by ComfyBuilder: No)
5. `win-amd` (Supported by ComfyBuilder: No)
6. `win-cpu` (Supported by ComfyBuilder: No)
7. `linux-nvidia` (Supported by ComfyBuilder: Yes)
8. `linux-amd` (Supported by ComfyBuilder: No)
9. `linux-intel-xpu` (Supported by ComfyBuilder: No)
10. `mac-mps` (Supported by ComfyBuilder: No)
11. `linux-nvidia-cu128` or alternative GPU profile (Supported by ComfyBuilder: No)

## Actionable Changes for ComfyBuilder Compatibility

To achieve complete compatibility with the desktop installation pipeline, several changes are required in the ComfyBuilder worker and backend packages.

### 1. Update Manifest Fields
The worker's manifest generation in `worker/internal/steps/steps.go` needs to add the missing fields. These are `pbs_release`, `uv_version`, `vendor_requirements`, `torchvision_version`, and `torchaudio_version`. The manifest `id` field should also map to the platform variant ID (e.g. `linux-nvidia`) instead of the deployment identifier.

### 2. Include Requirements File in Archive
The packaging step in `worker/internal/steps/steps.go` must copy the active `requirements-{vendor}.txt` file to the root of the workspace. It needs to include it in the `tar` command so the archive contains this file.

### 3. Expand Build Matrix
The backend's build matrix registry in `backend/internal/matrix/matrix.go` should be updated. Adding support for Windows, macOS, and other GPU vendors is necessary to enable non-Linux builds.

### 4. Upgrade Fake Builder
The fake builder in `backend/internal/build/fake/fake.go` must generate a real `.tar.gz` archive containing minimal directory structures. This is required so local development runs don't fail when the Desktop installer tries to extract the mock artifact.
